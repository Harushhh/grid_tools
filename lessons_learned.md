# Lessons learned

Read this before changing any script. Add a short entry after every fix (newest first): what the grid did, what
broke, what the fix is, and the test that now covers it. The point is that the same surprise is never debugged twice.

## How these entries are written
`YYYY-MM  insurer  - symptom`  then **Cause**, **Fix**, **Covered by**.

## 2026-11  all  - Documentation named places in a grid by cell address, row number and column letter
**Cause:** Playbooks, failure write-ups and spot-check recipes cited grid positions (column letters, row numbers, cell addresses, column ranges) that the next month's layout moves, so the text went stale and a spot-check recipe pointed at the wrong cell.
**Fix:** Every position was rewritten as labels and rules; each insurer got a dedicated reference file next to its skill; cellref_lint.py finds the forbidden forms in any markdown file of the project.
**Covered by:** tests/insurer_docs_tests.py (94 checks), check_regressions.py (dedicated references + lint), the refusal in learn.py lesson / note / skill
**Rule:** A place in a grid is named by its labels (title words, header chain, row label) and by the rule that finds it, never by an address; a number is checked by labels, not by address.

**Rule:** Rebuild the answer key from your reading of the grid in a scratch prototype first (one block at a time, diff by category), settle every difference with the user or the document, THEN write the script around header words and note words.
