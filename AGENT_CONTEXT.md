## 1. The mission and the rules that are never broken

Mission: input = one insurer circular / grid (.xlsx, .xlsb, .pdf) + the period (from_date, to_date); output = a CSV with the portal's 42 columns
(section 2) that the portal's "Rate Master" bulk upload accepts, plus a short report of what was written, what was not, and what needs a human.

Never-broken rules (all come from the user; "why" in section 9):

1. **Rates come only from the grid / circular.** Never invent a rate. Never ask the user for a rate. If a number cannot be read, ask WHICH
   cell/column to use (or to write 0 / leave rows out); never guess and never drop rows silently.
2. **Anything you cannot turn into logic is flagged, not guessed, asked about, or allowed to stop the run.** A note, a text rule, a colour-based rule,
   a region-specific exception: put `Manual Review Required: [the text]` in the `remarks` column of every row it may affect (a superset, never
   fewer rows), keep going. No fallback logic for combinations the note does not mention. (Section 4.)
3. **GRID / DOCUMENT problems are different from notes**: a missing column, a renamed sheet, an unreadable cell, a repeated cluster, dates that look wrong
   are put to the user as a numbered question (the `Asker`); under `--no-prompt` the script stops with the question as the error message.
4. **The two master workbooks are the authority for RTO group names and make/model group names** (section 3). A name not in them is flagged, never
   mapped to a similar one, never "fixed" silently. If an insurer grid has a make or RTO the master does not list: flag it so the user creates the mapping.
5. **`po_* = max(pi_* - 7, 0)`**; zero stays zero. Dates are written `DD/MM/YYYY` into every row. `IRDA` cells = `On OD` 15 (13 for 2W when CPA = Yes).
6. Where the user's own previous upload and the insurer's document disagree, **follow the document and list every difference** (ask first only if the
   document itself is ambiguous).
7. A general rule and a named special case combine additively (AND), not as an override; when a request could be read two ways across more than one axis,
   ask once, up front.
8. Never write to the Django portal repository (`C:\Users\Harsj\insurance-broker-portal1`), never push anything, never overwrite a file in `output\` the
   user may already have uploaded.
9. Never "improve" a script by refactoring it. Smallest change that fixes the problem; back up first (`backups\<name>.<yyyymmdd-hhmm>.py`; the folder is not under git).
10. A change is not done until `python check_regressions.py` prints `ALL OK` and the relevant `tests\` suites pass. Never `--bless` to hide a difference.
11. **An annexure, exception list or group that is not IN the document is not applied** - never carried over from an earlier circular, never assumed (user, 26 Oct 2026). A payout worded "... (Except RTOs listed in Sub Annexure N)" whose annexure is missing is written for the whole state(s) and flagged on exactly those rows; rows that exist only through the missing annexure (its preferred-RTO commission, the 40% preferred-city rows) are not written.

## 2. The output contract: the 42 columns

Order (identical in every script, `OUTPUT_COLUMNS`):

```
id, insurance_company, insurer_vertical, product, sub_product, policy_type, fuel_type, make_model_class, new_vehicle_makes, new_rto_list,
vehicle_age_min, vehicle_age_max, cc_min, cc_max, sc_min, sc_max, pi_od_rate, pi_tp_rate, pi_tp_2, pi_tp_3, pi_tp_4, pi_tp_5, pi_net_rate,
pi_flat_amount, pi_vli, pi_type, tariff_min, tariff_max, is_ncb, is_cpa, is_zd, from_date, to_date, user_id, veh_use, add_tnc, remarks,
po_type, po_od_rate, po_tp_rate, po_net_rate, po_flat_amount
```

One row = one rate card: a combination of (insurer, product, sub_product, fuel, make group, RTO group, age band, cc band, seat band, NCB/CPA/ZD flags,
tariff band, T&C) with a payin (`pi_*`) and a payout (`po_*`). Meaning and conventions:

| column | convention |
|---|---|
| `id` | `1` on every row (Liberty, RSA, United); Magma `1..N` |
| `insurance_company` | exact portal spelling, e.g. `LIBERTY GENERAL INSURANCE LTD`, `UNITED INDIA INSURANCE CO LTD`, `ROYAL SUNDARAM GENERAL INSURANCE COMPANY LIMITED`, `MAGMA HDI GENERAL INSURANCE CO LTD` |
| `insurer_vertical` | `Not Applicable` |
| `product` | `Private Car`, `TW`, `GCV 4W`, `GCV 3W`, `PCV 4W`, `PCV 3W`, `PCV 2W`, `MISCD` |
| `sub_product` | `1+1` (package / comprehensive, renewal), `1+3` (new car: 1 yr OD + 3 yr TP), `1+5` (new two wheeler), `SAOD`, `STP` (standalone third party / SATP). `3+3` (long-term package) and long-term liability have NO sub_product in the portal: not written, flagged |
| `policy_type` | `Renew` (1+1, STP, SAOD) / `New` (1+3, 1+5) |
| `fuel_type` | `Petrol`, `Diesel`, `CNG`, `LPG`, `Electric`; a grid column "non-diesel = petrol" is written once per fuel with the same rate |
| `make_model_class` | `NA`, `Car`, `BIKE`, `SCOOTER`, `Taxi`, `Other Bus`, `School Bus`, `Goods Carrying Rickshaw`, `Passenger Carrying Rickshaw`, `PCV 2W`, `MISCD-Tractor`, `MISCD-Others` |
| `new_vehicle_makes` | a make-group NAME from the make/model master (`Private_Car_ALL`, `GCV_4W_ALL`, `TW_ALL`, `BIKEALL`, `SCOOTERALL`, `BUS_ALL`, `TAXI_ALL`, `MISCD_ALL`, `PCV_3W_ALL`...). A comma list is allowed (`TATA,Ashok`) |
| `new_rto_list` | `ALLINDIA`, a comma list of state codes (`HR,KA,RJ`), or an RTO-group name from the RTO master. Commas split the list, so a cluster name must never contain one |
| `vehicle_age_min/max` | years, `0-99` when not age-banded. Bands are `[min, max)` in the mapping engine (lower inclusive, upper exclusive) |
| `cc_min/cc_max` | engine cc, or **GVW in kg** for goods vehicles. Convention: `cc_min = previous limit + 0.01`, `cc_max = limit + 0.01` (`1000.01-1500.01`); no lower limit `0`; no upper limit `99999` |
| `sc_min/sc_max` | seating capacity; `0-999` when not seat-banded; same `+0.01` convention |
| `pi_od_rate / pi_tp_rate / pi_net_rate` | payin in percent (30 = 30%). Exactly one of the three is non-zero, chosen by `pi_type`; `pi_tp_2..5`, `pi_flat_amount`, `pi_vli` = 0 |
| `pi_type` | `On Net` (premium base = net premium OD+TP; used for 1+1, 1+3, 1+5), `On TP` (STP), `On OD` (SAOD, or motor OD-only grids), `On OD and TP` (split rates) |
| `po_*` | same shape as `pi_*`, = `max(pi - 7, 0)`; `po_type` = `pi_type` |
| `tariff_min/max` | discount band, `0-100.01` unless the grid has discount bands (RSA GCV: `0-81.01` and `81.01-86.01`) |
| `is_ncb / is_cpa / is_zd` | `YES` / `NO` / `NA` |
| `from_date / to_date` | `DD/MM/YYYY`, typed by the user each run, identical on every row |
| `user_id` | `2966` (Liberty, Magma, RSA, Shriram, Go Digit); empty (United) |
| `add_tnc` | free-text T&C that is part of the key: `Ambulances`, `EX:Ambulances`, `New,<text>`, `Old,<text>`, `Educational Institution, Staff & School Buses`... |
| `remarks` | empty, or `Manual Review Required: [text]` (several joined with ` | `). Ignored by every comparison |

Duplicate detection: each script has `KEY_COLUMNS`; two rows with the same key are a defect (asked/stopped on, never written silently).
Numbers are written without trailing zeros (`27`, `27.5`); `fmt()` rounds to 4 decimals; RSA rounds payouts to 2 decimals (section 6, P-10).

Pan India Private Car (Liberty): comprehensive 27 / SAOD 25 on `ALLINDIA` are fixed settings (a deal, not in the grid) and must never be dropped.

## 3. The master lists (reference data, global, authoritative)

Two exports of the portal's masters live in `master\`: `rto_master.xlsx` (columns ID, RTO NAME, RTO CLUSTER = comma list of RTO codes; 5,828 groups,
`ALLINDIA` = 3,663 codes) and `make_model_master.xlsx` (595 make/model groups; `Private_Car_ALL` = 656 models). The newest file whose name contains
"rto"+"master" (resp. "make"+"model"+"master") wins, so a fresh download is simply dropped in.

**Since 30 Oct 2026 the RTO side of this section is switched off by default** (`RTO_NAMES = "cluster"` in the shared block, decision log 9): `new_rto_list` carries the bare cluster name,
`check_names` skips the RTO column, there is no 'RTO groups to create' sheet from it and the web app asks about no RTO name. How: each script's name builder wraps the group name it builds in
`rto_cluster(group, cluster)` (it remembers group -> grid cluster); `write_csv` calls `apply_cluster_names`, which maps the frame it writes (the frame the script keeps, the comparison with
`--ref` and the flags all still use the group names, so nothing else moved: in `GRID_RTO_NAMES=group` all 17 regression cases are byte-identical to the old baseline). Names the builders do not
register (Shriram's and United's master groups) lose their insurer prefix by `RTO_STRIP`. Two portal groups with one cluster name AND one key would collide: the run warns. The make side below is unchanged.

Rules:
- Every script calls `check_names(df, review, load_masters(ask), log)` before `review.report`. A name in `new_rto_list` / `new_vehicle_makes` that is not in the
  master is flagged on exactly its rows (`new_rto_list 'X' is not in the RTO master`), with the master's spelling as a HINT when it differs only in capitals or a stray
  leading/trailing `_`/space (`Masters.near`). The hint is never applied.
- The scripts build the master name from the grid's own label by a deterministic rule, then let the master judge it:
  Magma `MAGMA_APR26_` + cluster (spaces -> `_`); Liberty `LIBERTY_PC_TW_APR26_` (PC TW / TW SATP / PC SATP sheets), `LIBERTY_GCV_4W_<7.5T_APR26_` (CV <7.5T),
  `LIBERTY_GCV_4W>7.5T_APR26_` (CV >7.5T) + geo; RSA `ROYAL_SEPT26_` + `PVT_CAR_` / `PVT_STP_CAR_` / cluster; United per circular date (`circular_groups`); Go Digit `GO-DIGIT_OCT26_<segment>_<cluster>` (segments HCV, LCV, MCV, GCV3W, MISD, MISD-TRACTOR, PCV2W_3W_NON-EV, PCV3W_EV, PCV4W_UPTO-5, STAFF-BUS; two-wheelers `2W_1+1_TP_` / `2W_SAOD_`; cars `GO-DIGIT_PC_1+1_OCT26_` / `GO-DIGIT_PC_SAOD_OCT26_` / `GO-DIGIT_PC_TP_OCT26_`; `CLUSTER_NAME_EXCEPTIONS`).
  The month inside a prefix is the month the portal group was CREATED, not the grid's month. Change a prefix only when the master gets groups under a new one.
- A master group can itself be wrong or incomplete (it is the user's data). Compare it with the document and flag the difference, never work around it:
  United `UNITED_CAR_RTO_EX_Annexure*` lack 99 Madhya Pradesh RTOs; the 7-makes group lacks 7 models; `UNITED_RJ_GCV4W_2T-3.5T_Annexure-2` holds 27 of the
  circular's 31 Rajasthan RTOs; Liberty `>7.5T_APR26_Assam` (grid says ASSAM) and `...TELANGANA_` (trailing underscore).
- RSA GCV writes `TATA,Ashok` (master spelling), not `ASHOK`. United writes `Private_Car_ALL`, not `Private_Car_All`.
- State codes written by United/RSA (`new_rto_list` lists): 40 codes `AN AP AR AS BR CG CH DD DL DN GA GJ HP HR JH JK KA KL LA LD MH ML MN MP MZ NL OD OR PB PY RJ SK TG TN TR TS UA UK UP WB`.
  Two-code states: Odisha = `OD,OR`, Telangana = `TG,TS`, Uttarakhand = `UA,UK`. "Other than above States" = the 40 codes minus every state named by the other
  payouts of the same band. "All States" = `ALLINDIA`.

## 4. The remarks protocol (notes the script cannot apply)

Implemented once, in the shared block: `ManualReview`, `review.flag(text, rows)`, `review.report(df, log)`, `unknown_notes(texts, STANDING_NOTES)` (a text of 25 characters or more is a note; a SHORT text is one too when it is two words or more and says decline / exclude / not allowed - `SHORT_RULE_WORDS`, F-39).
A script that reads remarks cell by cell (Shriram) counts a leftover NUMBER as unread as well as leftover words (P-52): 'for NIL dep cases payout is 40%' must never lose its 40 in silence.
`check_regressions.py` FAILS a script that lacks `review = ManualReview()` and `review.report(df`.

- Collect candidate texts (cells long enough to be a rule, text above tables, guideline sheets, text outside PDF tables, a page with no table).
- Drop those already known to need no action (`STANDING_NOTES`: disclaimers, titles, rules already inside the grid's cells, rules the portal handles in its
  groups). Matching ignores spaces, capitals and punctuation, so a standing note whose NUMBER or MEANING changes ("CANNOT" -> "CAN") becomes new and is flagged.
- Flag the rows the note may affect: the clusters/makes it names (a state brings in all its clusters; NCR or no place named = the whole sheet). A superset, never fewer.
- The run never stops for a note and never asks about one. The summary prints "MANUAL REVIEW - N rows ... (k notes)".
- Comparisons with an earlier upload ignore `remarks`; the regression runner reports "ONLY the remarks column differs" separately from "the rates moved".

Patterns that read notes (RSA): every pattern USES UP the words it understands; any leftover text with a number is classified (region-discount note / unread) and
flagged. Matching a number is not understanding a sentence (section 8, F-12). When an insurer rewords a rule, add a pattern AND a test; never hard-code the month's number.

## 6. Pattern catalogue (reusable techniques - each cost a bug once)

P-1 **Find columns/rows by header text, never by position.** `label_key(x)` / `slab_key(x)` ignore spaces and capitals. Positions move (SPOC columns were added in July 2026).
P-2 **Never compare grid labels as raw text.** `<1.5L` vs `< 1.5L`. Missing = a question, never a silent skip.
P-3 **A header finder must require shape**: a short cell with 3+ filled cells beside it, not any cell containing a word (a note that says "all tonnages" was taken for the header).
P-4 **A row with numbers is a data row** even if its label has no digits (`D. Heavy`); open bands (`48 Ton and above`).
P-5 **Units**: Liberty and RSA cells are fractions (0.25 -> 25), Magma cells are percent (25); a cell of `0.635` where `63.5` is expected is asked about (`read_number`).
P-6 **Mirrored columns / blocks**: grids repeat a column for "Petrol/Non-Diesel", "Bike/Scooter", Old/New; `unique_segments`/`expand_mirrored` map one grid column to several output segments.
P-7 **Fuel expansion**: write one row per fuel with the same rate when the grid says "all fuel"/"non-diesel = petrol"; Electric is its own fuel (often a separate column or none).
P-8 **Age and weight/cc bands**: `+0.01` convention (P-8a: `1000 < cc <= 1500` -> `1000.01-1500.01`), open end 99999, `[min,max)` semantics in the engine; a band label without a lower limit starts at 0 (or, for buses, at "> 6 passengers").
P-9 **Cluster/geo names become portal group names by a prefix + exceptions table** (`CLUSTER_NAME_EXCEPTIONS`: Baroda -> VADODARA, Delhi NCR -> Delhi_NCR...). Commas inside a name split `new_rto_list` -> replace with `_`;
   double spaces survive (`REST_OF__TELANGANA`); text in brackets is dropped. A header spelt a new way gets the default name and may not exist in the portal: the master check flags it.
P-10 **Rounding**: round once, from the full-precision cell, half up (Excel style). Rounding to 4 decimals first created false ties (33.125 -> 33.12).
P-11 **Notes -> rules (RSA)**: several wordings per rule ("3% lower", "reduced by 3", "deduction of three", "w.e.f. 22 Oct 2026"), each pattern consumes the words it understands, leftovers are classified and flagged.
P-12 **Rules that depend on an effective date**: read "effective from" / "existing grid continues"; compare with from_date; flag when different; a setting (`UNCHANGED_SHEETS`) decides what to do with a continuing sheet.

## 12. The self-learning protocol (run after EVERY grid, before saying "done")

The system learns only if each run leaves something behind. Do all that apply; each takes a minute. The helper `learn.py` (in
`.claude/skills/grid-converter/scripts/`) does the file mechanics.

1. **Lesson entry** in `lessons_learned.md` (newest first): `YYYY-MM  insurer  - symptom`, then **Cause**, **Fix**, **Covered by**, plus **Rule** if it generalises.
   `python .claude/skills/grid-converter/scripts/learn.py lesson --insurer united --title "..." --cause "..." --fix "..." --covered "..." [--rule "..."]`
2. **Layout snapshot** after the user accepts a good output: `python grid_doctor.py snapshot <grid> --name <insurer_monYY>` (PDF: skip, doctor cannot read it).
3. **Regression case** for the new grid (copy to `regression\inputs\`, expectations from the run, `--bless` only when the user confirmed the output):
   `python .claude/skills/grid-converter/scripts/learn.py case --name <insurer_monYY> --script <script>.py --grid <path> --from-date .. --to-date .. [--ref <csv>] --answers "" y y --note "..."`
4. **Tests** for every behaviour you added (`tests\<name>_tests.py`); assertions on non-empty selections (P-21).
5. **This file**: add to section 7 (playbook), section 6 (a new pattern P-n), section 8 (a new F-n), section 9 (a decision with its date), section 10 (what is still open),
   and bump "Last updated". If you learned something that contradicts this file, correct it - do not append a contradiction.
6. **The insurer's skill** (`.claude/skills/<insurer>-grid/SKILL.md`; one per insurance company - shriram, sbi, icici, liberty, magma, rsa, united, godigit): the short memory the next run loads FIRST. One dated bullet for each fact that holds for THAT insurer from now on - Status
   (first build / accepted / row counts), Rules the user has set (do not re-ask), Traps seen, Open items:
   `python .claude/skills/grid-converter/scripts/learn.py skill --insurer shriram --section status|rules|traps|open --text "..." [--date "4 Nov 2026"]`
   A rule the user gives goes into BOTH the decision log (section 9) and the skill; a bullet that turns out wrong is edited in place, never contradicted by a new one. A new script gets its skill in the same job (5.3 step 6; `tests/skills_tests.py` and `check_regressions.py` fail without it).
7. **Docs**: `CLAUDE.md` (current state of each script), `README.md` (how to run), keep the numbers (rows / flagged / checks) true.
8. **Memory** (Claude Code auto-memory), only what is not derivable from the repo: user decisions and preferences, with the reason.
9. Check the loop: `python check_regressions.py` ALL OK, `python tests/run_tests.py` ALL OK (`--all` if you touched the shared block).
